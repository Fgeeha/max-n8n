# Бот без кода: информация + заявка «перезвоните мне»

Сценарий `workflows/max-bot-simple.json` для тех, кто не программирует.
В нём нет ни одной ноды Code: только готовые блоки n8n — Set, Switch,
Postgres, Execute Workflow. Бот показывает информационные экраны по кнопкам
и принимает заявку на обратный звонок.

```
/start ─► Главное меню
            ├─ 🏢 О компании ─────► текст + [🌐 сайт] [📞 Перезвоните мне] [⬅️ В меню]
            ├─ 🕒 Режим работы ───► текст + [📞 Перезвоните мне] [⬅️ В меню]
            ├─ 📍 Контакты ───────► текст + [📋 скопировать телефон] [📞] [⬅️]
            └─ 📞 Перезвоните мне ► «нажмите кнопку или напишите номер»
                                      └─► [📱 Отправить мой номер] или номер текстом
                                            └─► заявка в callback_requests
                                                + «✅ Спасибо, заявка №N принята»
                                                + 🔔 уведомление каждому из ADMIN_IDS

всё остальное (любой текст без номера, незнакомая кнопка) ─► Главное меню
```

## Включить

В `.env`:

```env
BOT_SCENARIO=simple
ADMIN_IDS=297701163        # кому слать заявки; свой user_id покажет make requests
```

Затем `make provision` (локально) или `make provision-prod`. Оба движка,
`demo` и `simple`, лежат в n8n одновременно; какой из них отвечает, решает
`BOT_SCENARIO`. Вернуться к демо-боту с каталогом — `BOT_SCENARIO=demo` и
снова `make provision`.

## Что такое экран

Откройте в n8n сценарий **«MAX bot — простой: информация + заявка на звонок
(без кода)»**. Каждый блок **«Экран: …»** — это нода Set с двумя полями:

| Поле | Что это |
|---|---|
| `text` | текст сообщения. Markdown: `*жирный*`, `_курсив_` |
| `buttons` | кнопки под сообщением: список рядов, в ряду — список кнопок |

Пример поля `buttons` — два ряда, в первом две кнопки:

```json
[
  [{"type":"callback","text":"🏢 О компании","payload":"about"},
   {"type":"callback","text":"🕒 Режим работы","payload":"hours"}],
  [{"type":"callback","text":"⬅️ В меню","payload":"main"}]
]
```

Типы кнопок:

| `type` | Что делает | Обязательные поля |
|---|---|---|
| `callback` | открывает экран с ключом `payload` | `text`, `payload` |
| `link` | открывает сайт | `text`, `url` |
| `clipboard` | копирует `payload` в буфер обмена | `text`, `payload` |
| `request_contact` | просит пользователя поделиться номером | `text` |

`payload: "main"` всегда ведёт в главное меню — отдельного правила для него не
нужно.

## Поменять текст или кнопки

1. Открыть блок «Экран: …» двойным щелчком.
2. Поправить `text` или `buttons`.
3. Закрыть блок, нажать **Save** в правом верхнем углу.

Бот подхватывает правку на следующем сообщении, перезапуск не нужен.

В тексте главного меню стоит выражение `{{ $json.name }}` — это имя
пользователя из MAX. Такое поле начинается с `=`; если знак убрать, бот
напишет буквально `{{ $json.name }}`.

## Добавить экран

Например, экран «Доставка» с ключом `delivery`:

1. Скопировать блок «Экран: Режим работы» (Ctrl+C, Ctrl+V), переименовать в
   «Экран: Доставка», написать текст и кнопки.
2. Открыть блок **«Какая кнопка?»**, нажать **Add Routing Rule**: слева
   `{{ $json.payload }}`, условие *is equal to*, справа `delivery`. В
   **Rename Output** написать «Доставка». Правило должно стоять **выше**
   правила «Заявка».
3. Соединить новый выход «Доставка» с блоком «Экран: Доставка», а «Экран:
   Доставка» — с блоком «Ответить».
4. На нужном экране (обычно в главном меню) добавить кнопку
   `{"type":"callback","text":"🚚 Доставка","payload":"delivery"}`.
5. **Save**.

Ключ `payload` — латиницей, без пробелов. Кнопка с ключом, для которого нет
правила, откроет главное меню.

Удалить экран — в обратном порядке: убрать кнопки, ведущие на него, удалить
правило в «Какая кнопка?», удалить блок.

## Заявка на звонок

Заявкой считается сообщение, в котором **6 и больше цифр** (телефон в любом
формате), или **контакт**, отправленный кнопкой «📱 Отправить мой номер».
Сообщение без номера («перезвоните мне», «привет») в заявку не превращается —
бот покажет главное меню.

Заявка попадает в таблицу `callback_requests` и уходит сообщением каждому
`user_id` из `ADMIN_IDS`. Пустой `ADMIN_IDS` — уведомлять некого, заявка всё
равно в базе.

Посмотреть заявки и узнать `user_id` написавших:

```bash
make requests
```

Первая таблица — последние 20 заявок, вторая — кто писал боту. Чтобы получать
уведомления, напишите боту любое сообщение, найдите свой `user_id` во второй
таблице, впишите в `ADMIN_IDS` и выполните `make provision` — правки `.env`
доезжают до n8n только при пересоздании контейнера.

Текст уведомления — блок «Сообщение админу», текст подтверждения клиенту —
«Экран: Спасибо». Правятся так же, как остальные экраны.

## Чего здесь нет

- Многошаговых форм и памяти между сообщениями: бот отвечает на каждое
  сообщение независимо. Нужны шаги (спросить имя, потом номер) — это движок
  `demo` и его нода «Сценарий», см. [`scenarios.md`](scenarios.md).
- Проверки номера: сохраняется как написали. Оператор увидит и перезвонит.
- Статусов заявки: `status` меняется только руками в базе.

Что общего с демо-ботом: источники апдейтов, защита от повторной доставки,
учёт пользователей и блок «Отправить в MAX» — те же самые.
