# Bot API MAX — что выяснено опытным путём

База: `https://botapi.max.ru`. Официальная документация: <https://dev.max.ru/docs>.
Всё ниже проверено запросами к живому API 2026-09-04.

## Авторизация

Токен передаётся **заголовком**, query-параметр объявлен устаревшим:

```
Authorization: <MAX_BOT_TOKEN>
```

Без `Bearer`. Попытка передать `?access_token=` возвращает:

```json
{"code":"verify.token","message":"Query parameter access_token is deprecated, use Authorization header"}
```

## Используемые методы

| Метод | Назначение |
|---|---|
| `GET /me` | Проверка токена, данные бота |
| `GET /chats?count=N` | Список чатов, где состоит бот |
| `GET /updates?marker=&limit=&timeout=` | Long polling очереди обновлений |
| `POST /messages?chat_id=` / `?user_id=` | Отправка сообщения |
| `POST /answers?callback_id=` | Ответ на нажатие inline-кнопки |
| `POST /subscriptions` | Регистрация вебхука (в этой сборке не используется) |

## Очередь обновлений и marker

`GET /updates` возвращает `{"updates": [...], "marker": <число>}`.

- Запрос **без** `marker` только читает очередь, ничего не подтверждая.
  Поэтому `scripts/max-api.sh updates` безопасен — очередь не теряется.
- Запрос **с** `marker` подтверждает всё до этой позиции. Именно так
  сценарий продвигается по очереди.
- Очередь копится, пока её никто не вычитывает. На боевом токене там
  оказался суточный хвост сообщений из групповых чатов.

Из этого следует, что **на один токен должен быть ровно один потребитель**.
Второй long polling или параллельно включённый вебхук будут отбирать друг у
друга обновления.

## Типы обновлений, которые разбирает сценарий

- `message_created` — `message.body.text`, отправитель в `message.sender`,
  адресат в `message.recipient` (`chat_type`, `chat_id`, `user_id`).
- `message_callback` — нажатие inline-кнопки. `callback.callback_id`,
  `callback.payload`, пользователь в `callback.user`.
- `bot_started` — пользователь открыл диалог с ботом. Сценарий трактует его
  как `/start`.

`chat_type` равен `dialog` для лички и `chat` для группы — это единственный
надёжный признак, по которому сценарий отсекает групповые чаты.

## Клавиатура

Кнопки — это вложение типа `inline_keyboard` внутри `attachments`:

```json
{
  "text": "Выберите раздел:",
  "format": "markdown",
  "attachments": [{
    "type": "inline_keyboard",
    "payload": {
      "buttons": [
        [{"type": "callback", "text": "📋 Каталог", "payload": "catalog"}],
        [{"type": "link", "text": "🌐 Сайт", "url": "https://example.com"}]
      ]
    }
  }]
}
```

`buttons` — массив рядов, ряд — массив кнопок. У каждой кнопки обязателен `text`.

| Тип кнопки | Обязательные поля | Что делает |
|---|---|---|
| `callback` | `payload` | Присылает `message_callback` |
| `link` | `url` | Открывает ссылку |
| `request_contact` | — | Запрашивает телефон пользователя |
| `request_geo_location` | — | Запрашивает геопозицию |
| `message` | — | Отправляет боту заранее заданный текст |
| `open_app` | — | Открывает мини-приложение |
| `clipboard` | `payload` | Копирует текст в буфер обмена |

### Проверка формы тела без отправки

API валидирует тело **до** поиска чата. Это удобно: можно проверить схему
сообщения, не отправляя его никому.

```bash
# корректное тело -> chat.not.found (значит, схема принята)
# кривое тело     -> proto.payload
curl -X POST -H "Authorization: $MAX_BOT_TOKEN" -H 'Content-Type: application/json' \
  -d '<тело>' 'https://botapi.max.ru/messages?chat_id=1'
```

## Ответ на нажатие кнопки

`POST /answers?callback_id=<id>` с телом:

```json
{"message": {"text": "...", "attachments": [ ... ]}}
```

Если передан `message`, исходное сообщение **заменяется на месте** — так
работает навигация по меню. Альтернатива — `{"notification": "текст"}`,
всплывающее уведомление без изменения сообщения.

`callback_id` одноразовый и живёт недолго: на просроченный или выдуманный id
API отвечает `{"code":"proto.payload","message":"callback_id: Callback identifier is invalid"}`.

## Форматирование текста

Поле `format`: `markdown` или `html`.

Markdown у MAX свой, не CommonMark: `*курсив*`, `**жирный**`, `~~зачёркнутый~~`,
`++подчёркнутый++`, `^^выделенный^^`, `` `моноширинный` ``, `[текст](url)`,
`# заголовок`, `> цитата`.

## Вложения: ограничения

- Не больше 12 вложений на сообщение.
- Вложение с кнопками — максимум одно.
- Файл (`file`) сочетается только с кнопками, но не с изображением или видео.
- Медиа сначала загружается через `POST /uploads`, потом её `token`/`url`
  подставляется во вложение.
